# landing
1. Что делал сам, а что поручил ИИ

Делал сам: формулировал бизнес-логику (убрал тип «вопрос», оставив только заказы и подписки), управлял Git (ветки backend, main, слияния, пуши в GitHub), подключал репозиторий к Vercel, настраивал переменные окружения для Telegram-бота в панели хостинга и локально устанавливал зависимости через npm.

Поручил ИИ: первоначальную генерацию кода формы и бэкенда, архитектурное разделение монорепозитория, конфиг vercel.json под мультисервисный проект.

2. Где ИИ ошибся и как это было замечено

Несовместимость библиотек SQLite: ИИ сгенерировал код с sqlite3, но в package.json бэкенда остался better-sqlite3. Ошибка вскрылась прямо в логах сборки Vercel: Error: Can't resolve 'sqlite3'. Пришлось вручную переустанавливать пакеты в папке backend.

Ошибка записи в файловую систему (SQLITE_CANTOPEN): ИИ забыл, что Serverless-среда Vercel открыта только для чтения. При отправке заявки бэкенд возвращал статус 500, а в логах висела ошибка errno: 14, SQLITE_CANTOPEN. Проблему решили переносом пути к базе в директорию /tmp/leads.db и явным добавлением флагов создания файла (OPEN_CREATE).

Потенциальное падение без .env: ИИ изначально не заложил мягкую обработку отсутствия ключей Telegram, из-за чего любой деплой без введенных переменных в UI ронял роут с 500 ошибкой.

3. Что не успел или сделал бы иначе

Внешняя база данных: SQLite в Serverless сохраняет файл в /tmp, который стирается при перезапуске лямбды. В будущем сразу подключил бы облачную базу (PostgreSQL через Supabase или Turso для SQLite), чтобы гарантировать постоянное хранение данных.

Дизайн: не успел отредактировать форму в отправки вопросов.
